🏗️ System Architecture

System architecture, service boundaries, data flow, and communication standards.

On this page

OverviewService Boundaries Data FlowCommunication StorageNetworking

Overview

Evershade is a microservices architecture where each service has a single responsibility. Services communicate via HTTP/JSON REST APIs and async events through Redis. Greenie acts as the central orchestrator and API gateway.

Service Boundaries

LayerServicesResponsibility
GatewayGreenieAPI gateway, auth, routing, orchestration
CoreSlinker, Trapper, GobberCode execution, web scraping, storage
SupportSneaker, Hider, Poltergeist, ShrewdObservability, secrets, notifications, LLM
FrontendSlammer, SpeedyWeb dashboard, CLI tool

Data Flow

Request Flow (Synchronous)

  1. Client → Greenie (port 8080)
  2. Greenie authenticates request
  3. Greenie → Target service (internal network)
  4. Target service processes and responds
  5. Greenie → Client (aggregated response)

Event Flow (Asynchronous)

  1. Service publishes event to Redis
  2. Redis distributes to subscribers
  3. Subscribers process events independently
  4. Results stored in respective databases

Communication Standards

HTTP/JSON REST

  • ✓ All services expose REST APIs
  • ✓ Bearer token authentication
  • ✓ Standard response format with success, data, error
  • ✓ HTTP status codes for error handling

Redis Events

  • ✓ Pub/Sub for real-time events
  • ✓ Streams for persistent event logs
  • ✓ Queues for task distribution

Networking

Docker Network

  • ✓ All services on evershade-network bridge network
  • ✓ Services communicate via Docker DNS (service name)
  • ✓ Only Greenie (port 8080) published to host
  • ✓ Slammer (port 5173) published in full profile

External Access

  • ✓ Caddy reverse proxy for TLS (proxy profile)
  • ✓ Automatic HTTPS with Let's Encrypt
  • ✓ Subdomain routing for services
Design Principle: Each service is independently deployable and replaceable. Optional services degrade gracefully when unavailable.
