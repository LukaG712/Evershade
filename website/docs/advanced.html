Platform Internals

Request Flow

  1. Client sends request to Greenie (port 8080)
  2. Greenie authenticates via Bearer token
  3. Greenie routes to appropriate service (Slinker, Trapper, Gobber, etc.)
  4. Service processes request and returns response
  5. Greenie aggregates and returns to client

Event System

Services communicate via events for async operations. Events are published to Redis and consumed by interested services.

Performance Tuning

Greenie

  • ✓ Increase MAX_WORKERS for concurrent request handling
  • ✓ Enable SQLite WAL mode for better write performance
  • ✓ Use connection pooling for database access

Slinker

  • ✓ Increase MAX_CONCURRENT_WORKERS for parallel tasks
  • ✓ Use container isolation for better resource control
  • ✓ Configure workspace cleanup policies

Trapper

  • ✓ Increase CRAWL_MAX_CONCURRENCY for faster crawling
  • ✓ Use Redis cluster for high-throughput queues
  • ✓ Configure browser instance pooling

Plugin System

Plugins extend platform functionality without modifying core services. Plugins are Python packages installed in the plugins/ directory.

# Install a plugin
evershade plugins install my-plugin

# List installed plugins
evershade plugins list

# Uninstall a plugin
evershade plugins uninstall my-plugin

MCP Servers

Model Context Protocol (MCP) servers provide standardized tool access for agents. Configure MCP servers in Greenie's settings.

curl -X POST http://localhost:8080/api/mcp/servers \
  -H "Authorization: Bearer $EVERSHADE_GREENIE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "filesystem",
    "transport": "stdio",
    "command": "npx",
    "args": ["-y", "@modelcontextprotocol/server-filesystem", "/workspace"]
  }'

Custom Integrations

Build custom integrations using the webhook system in Gobber.

curl -X POST http://localhost:8085/api/webhooks \
  -H "Authorization: Bearer $EVERSHADE_GOBBER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "ci-trigger",
    "url": "https://ci.example.com/webhook",
    "events": ["task_complete", "mission_complete"],
    "secret": "webhook-secret"
  }'

Debugging

Enable Debug Logging

# Set log level to DEBUG
sed -i 's/EVERSHADE_LOG_LEVEL=INFO/EVERSHADE_LOG_LEVEL=DEBUG/' .env
docker compose restart

View Logs

# All services
docker compose logs -f

# Specific service
docker compose logs -f greenie

# Last 100 lines
docker compose logs --tail=100 greenie

Run Diagnostics

evershade doctor
Tip: Use evershade status for a quick health check of all services.
