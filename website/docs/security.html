🔐 Security Model

Security principles, authentication, container hardening, and best practices.

On this page

PrinciplesAuthenticationNetwork SecretsCSRFRate Limiting Best Practices

Security Principles

  • ✓ Least privilege – Every service runs with minimal permissions
  • ✓ Defense in depth – Multiple layers of protection
  • ✓ Network isolation – Only the gateway is exposed
  • ✓ Secrets protection – Credentials encrypted at rest, never logged
  • ✓ Untrusted content – All external content treated as data, not instructions

Authentication

MethodDescription
Service-to-serviceBearer token API keys with constant-time comparison
Browser usersUsername/password with bcrypt (12 rounds), HMAC-signed session cookies
RBACAdmin, user, and viewer roles

Network Security

  • ✓ Only Greenie (port 8080) published to host
  • ✓ All other services on internal Docker network
  • ✓ Caddy reverse proxy for TLS in server mode

Container Hardening

  • ✓ cap_drop: ALL – No Linux capabilities
  • ✓ no-new-privileges – No privilege escalation
  • ✓ read_only: true – Immutable root filesystem
  • ✓ tmpfs mounts for writable directories
  • ✓ Resource limits (CPU, memory, processes)

CSRF Protection

Greenie implements CSRF protection for cookie-authenticated sessions using HMAC-signed tokens with the double-submit cookie pattern. Bearer-authenticated API clients are exempt.

Rate Limiting

OperationLimit
Auth failures10 per 60s per IP
LLM requests20/min
Code execution5/min
Default60 requests/min

Best Practices

For Beginners

  • ✓ Generate strong API keys with openssl rand -hex 32
  • ✓ Never commit .env to Git
  • ✓ Use minimal profile first
  • ✓ Keep Docker updated
  • ✓ Backup regularly with evershade backup

For Production

  • ✓ Enable TLS with Caddy proxy profile
  • ✓ Restrict firewall – only ports 80/443
  • ✓ Rotate keys periodically
  • ✓ Monitor logs with Sneaker alerts
  • ✓ Use EVERSHADE_MODE=server
  • ✓ Enable rate limiting
  • ✓ Use container isolation for Slinker
