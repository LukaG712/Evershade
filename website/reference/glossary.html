📖 Glossary

Key terms and concepts used throughout the Evershade platform.

TermDefinition
AgentAn AI-powered worker that executes tasks. Agents have a name, runner (Junie), and guidelines that define their behavior.
Agent HarnessThe execution framework that provides Spec Mode, droids, skills, hooks, and environments for agents.
Container IsolationRunning agent tasks in isolated Docker containers to prevent access to host resources.
DroidA specialized agent configuration with predefined capabilities (coder, researcher, reviewer, deployer).
EvershadeThe self-hosted AI agent platform. Named after Evershade Valley from Luigi's Mansion: Dark Moon.
Feature FlagA toggle that enables or disables features without code changes. Managed by Gobber.
GobberStorage service providing SQLite databases, knowledge graph, Obsidian vault integration, and semantic search.
GreenieCentral orchestrator and API gateway. All requests flow through Greenie.
HiderEncrypted secrets management service using AES-256-GCM encryption.
HookAn event-driven callback triggered at specific points in the agent lifecycle.
Junie CLIThe JetBrains Junie command-line interface used by Slinker for code execution.
Knowledge GraphA semantic network of interconnected data stored in Gobber, supporting vector-based search.
MCP ServerModel Context Protocol server providing standardized tool access for agents.
MilestoneA discrete step within a Mission. Milestones execute sequentially with validation between each.
MissionA multi-step AI workflow managed by Mission Control, consisting of milestones with validation.
ObservabilityThe ability to monitor system state through metrics, traces, and logs. Provided by Sneaker.
OTLPOpenTelemetry Protocol – standard format for exporting metrics, traces, and logs.
PluginA Python package that extends platform functionality without modifying core services.
PoltergeistNotification delivery service supporting Slack, Discord, Email, and Telegram.
ProfileA Docker Compose profile that determines which services are started (minimal, standard, full).
RBACRole-Based Access Control – admin, user, and viewer roles for API and dashboard access.
RunA single execution of an agent task, including input, output, and metadata.
ShrewdLLM provider abstraction service supporting OpenAI, Anthropic, Google AI, and Ollama.
SlinkerCode execution engine that runs AI agents against codebases in isolated worktrees.
SlammerReact-based web dashboard for platform management.
SneakerObservability service collecting metrics, traces, logs, and managing alerts.
SpeedyCLI tool providing terminal-based platform management via the evershade command.
Spec ModeStructured task definition mode with input/output schemas, constraints, and validation rules.
SkillA reusable capability that agents can use, organized hierarchically with inheritance.
TrapperWeb scraping and crawling service using Playwright for headless browser automation.
ValidationChecks run after each milestone to verify success. Failed validation triggers fix-revalidate cycles.
WorkflowA defined sequence of steps that agents execute, managed by Greenie.
WorkstationAn isolated Docker container providing a full development environment for agent execution.
WorktreeA Git worktree – an isolated checkout of a repository used by Slinker for code execution.
